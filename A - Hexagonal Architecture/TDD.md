¿Quieres usar Test Driven Development (TDD) pero no sabes por donde empezar?  
  
Familiarízate con las tres leyes de TDD  
  
Estas reglas son los principios de uso de TDD en la práctica.  
  
Nos obligan a cambiar sólo una cosa a la vez. ¡Nos obligan a aplicar babysteps!  
  
No se permite:  
  
1. Escribir código de producción a menos que sea para pasar un test fallido.  
  
2. Escribir más de un test que sea suficiente para fallar; y los errores de compilación son errores.  
  
3. Escribir más código de producción que el necesario para pasar el test que falla.  
  
Práctica realizando katas  
  
Las katas son pequeños ejercicios de programación que se centran en pequeños problemas.  
  
Resolver katas es una excelente manera de aprender TDD.  
  
¡Elige un Kata! Puedes encontrar muchos de ellos aquí: [https://buff.ly/3GzdQEG](https://buff.ly/3GzdQEG)  
  
Sigue el ciclo de TDD (red-green-refactor)  
  
Sigue las fases repetidamente en iteraciones:  
  
1. Red: Escribir una prueba fallida  
2. Green: hacer que pase la prueba fallida  
3. Refactor: Refactoriza tu código (incluyendo tus pruebas también)  
  
Practica mucho  
  
Los buenos en algo simplemente han prácticado más.  
  
¡Asegúrate de tener fundamentos sólidos resolviendo múltiples ejercicios de Kata!  
Aplica TDD en tu proyecto  
  
Una vez que hayas terminado con Katas, es hora de poner en práctica TDD en tu proyecto.  
  
¡Empieza sencillo!  
  
¡Comienza con una prueba fallida para una función o una clase que quieras implementar!  
  
¡Y ten siempre en cuenta las tres leyes de TDD!  
  
¿Por qué te ayudará TDD?  
  
TDD te obligará a:  
- trabajar en ciclos cortos  
- escribir pruebas automatizadas  
- hacer refactorización continua  
- analizar continuamente los requisitos  
- escribir el código de producción más óptimo
