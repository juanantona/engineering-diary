7 pasos para mejorar tu relación con el código y convertirlo en tu aliado, no tu enemigo en el futuro:  
  
1. Desconecta de la sociedad de consumo.  
  
Acaba con el desarrollador que llevas dentro que persigue modas como un asno una zanahoria.  
  
Cuando antes te des cuenta de que tratar de estar de forma constante a la última te perjudica más que beneficiarte, mejor.  
  
2. Analiza donde va a parar la lógica de tu negocio.  
  
Toma el control del dominio de tu proyecto.  
  
Extraer la lógica del negocio te permite crear tests en la parte más importante de un proyecto.  
  
O tú controlas el dominio del proyecto o las librerías lo harán por ti.  
  
3. Economía de aprendizaje.  
  
Hasta que entiendas bien los principios básicos del softwate, hazlo todo manualmente.  
  
Inyección de dependencias, dobles de tests, event bus, etc.  
  
Las librerías para estos principios son muy útiles solo cuando ya entiendes la magia que hay por detrás.  
  
4. Elimina acoplamientos.  
  
Diseña un plan que te permita desacoplarte de librerías y frameworks poco a poco.  
  
En función de cuál sea tu situación de acoplamiento exacta, es posible que este sea el paso más complicado (y el más largo) de todos, pero no desesperes.  
  
5. Crea test de integración y aceptación  
  
Cuando el dominio esté aislado, desacoplado y con tests, es momento de empezar a crear otros tipos de tests donde reemplaces infraestructura con objetos dobles o interceptores simulando escenarios de prueba.  
  
6. Cuando el diseño de tu software este saneado y entiendas bien los principios. Ha llegado la hora de usar librerías para facilitar.  
  
Inyección de dependencias, dobles de tests, event bus, etc.  
  
Mi consejo es que no escuches cantos de sirenas y elijas según tus necesidades.  
  
7. Comparte mucho conocimiento con el equipo, los proyectos no los mantiene greenfield una sola persona:  
  
Pair programming, coding dojos, revisiones en directo, etc..  
  
Saber crear software de calidad.  
  
Eso quiere decir saber de diseño de software, testing y saber trabajar con código legado.
